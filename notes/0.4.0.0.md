# Plex Media Manager 0.4.0.0

### New
- A **System** section for admins (Health, Problem files, Logs, Audit, Backup) at `/system/<page>`; see docs/operations.md.
- **Health**: status cards (OK, warning, fail) with a fix hint for the database, disk space, Plex, Sonarr, Radarr and Bazarr, workers, queue, tools and recent errors, also as JSON (`GET /api/ops/health`).
- **Problem files**: files that keep failing or can't be read, with Retry and Ignore; the item page warns about them.
- **Direct-play advisor** on the item page (all four layouts): whether Plex Web, Apple TV, Roku, Android TV, smart TVs and the desktop app would direct play, direct stream or transcode the file, and why, from the index alone.
- **Backups**: back up now, scheduled (daily or weekly, keep the newest N), download, delete, and restore from a file with a preview and a confirmation; the file is validated first and the current database is kept as a backup. Secrets are left out unless you ask, and marked when included.
- **Audit log** of sign-ins, account and role changes, settings changes, applies, restores, backups and trash deletions, with filters.
- **Logs** viewer: the app now writes a rotating log file; live tail, level, text and file filters, download and clear. Tokens, API keys, passwords, cookies and Authorization headers are redacted in what you see and download.
- **Metrics**: `/metrics` (Prometheus) and `/metrics.json` (Home Assistant), off by default, protected by a token or a private-network check.
- Settings, System tab: backups, metrics and the log file.
- Every rewritten file is verified before it replaces the original: its streams, languages, flags and codecs are compared with the plan, its duration with the source's, a few seconds are decoded (start, middle and end with Full) and every subtitle track is read. A file that fails keeps the original untouched and the item fails with the reason. On by default (Settings, Safety and housekeeping: Full, Quick or Off, which asks for a confirmation); workers check their rewrites the same way.
- Worker limits (Settings, Workers, and per worker with its Limits button): no new job while a worker's GPU is too hot (83 °C by default, until it is 10 °C cooler) or draws too much power, and none in its quiet hours (e.g. Mon-Fri 22:00-07:00). A running file always finishes, unless the GPU reaches the hard limit (92 °C): then it is handed back untouched and queued again. GPU readings are read-only (nvidia-smi, or the driver's NVML inside the Flatpak). The Workers dialog and the Overview show why a worker waits, and the Workers dialog shows each GPU's temperature.
- Workers can update themselves (opt-in per worker): a systemd user timer on the worker machine (`setup-worker.sh --self-update-timer`) installs a newer release from the public feed when it works with the main app, inside the worker's update hours, and only while the worker is idle. The worker's Flatpak gets no host permission. Updates start once worker bundles are published in the feed (not yet in this release). See docs/workers.md.

### Changed
- The database gets two new tables, `audit_log` and `problem_ignores`, created automatically at start-up. Back up before upgrading, as always.
