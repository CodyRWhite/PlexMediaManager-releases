# Plex Media Manager 0.7.0.0

### New
- **Pause and Resume a worker, or all of them, without faking it with pause hours.** A worker's own page has a **Pause / Resume** button (saved in its settings, so it survives a restart; the state reads "paused (by you)"), the Workers dialog has one per worker (admins, audit-logged as `worker_pause` / `worker_resume`), and a **Pause all workers** switch with an optional reason such as "NAS scrub" covers every worker and This server (audit-logged, shown on the Overview's live activity and in the Workers dialog). A pause lets the file in progress finish and takes no new work; either side's pause wins, and the reason says which. System → Health warns while all workers are paused. Older workers just obey the main app's pause. If you paused a worker with all-day pause hours, clear them. New `PUT /api/workers/{name}/settings` field `paused`, `GET`/`PUT /api/workers/pause-all`, the worker page's `PUT /api/pause`, and the worker setting `worker_paused` (use the button, not the form).
- **The direct-play check covers many more devices and you choose which.** The item page now judges Fire TV (Stick HD / Lite, Stick 4K, 4K Max 1st and 2nd gen, Cube), Nvidia Shield, Fire TV on Vega OS, Chromecast with Google TV (HD and 4K), Chromecast casting, Google TV Streamer, Roku (4K / Ultra and HD), LG webOS, Samsung TVs by era, Xbox, PlayStation, iPhone / iPad, Android phones and tablets, and every Apple TV (HD, 4K 1st to 3rd gen and the 2026 4K 4th gen), each with its own codec, HDR, Dolby Vision, resolution, audio (including passthrough-only DTS / TrueHD) and subtitle limits. Pick the devices your household uses under Settings, Appearance, *Devices in the direct-play check* (`directplay_profiles`); the badge then reads like "Direct play on 6 of 7 devices". The default is a set of 17 common devices (every Apple TV, Plex Web, Roku, Fire TV, Android and Google TV, Samsung, iOS), to keep the item page short.
- **The details suggest the one fix that helps several devices.** When two or more chosen devices (or Plex Web) only transcode because of audio (such as EAC3 or DTS) or because of image subtitles, the details say so, for example that a stereo AAC track would let Plex Web and 3 others direct play, or that a text copy of PGS subtitles (PMM can make one by OCR) would avoid burn-in. Nothing is planned or changed.
- **Use the devices seen in Plex.** PMM now remembers the players Plex shows (model, platform, name, when last seen, files started) and a button beside the device choice ticks the matching profiles, listing the players it couldn't match (`GET /api/ops/direct-play/devices`). Model codes such as `AFTKRT` or `AppleTV14,1` are matched first, then keywords.
- **Samsung and LG TVs burn in subtitles when the audio is transcoded**, which the check now predicts: a text subtitle shown together with EAC3 or DTS audio the TV can't play transcodes the video too.
- **Scheduled tasks** and **System, Tasks** (`/system/tasks`, admins): every recurring job the main app runs (library sweep, Auto-apply, On Deck, Plex playback, artwork and labels, daily summary, update check, backups, the silent-worker check, trash purge, subtitle viewer cache clean-up, the Overview's live cards and the start-up fills) in one registry, with its schedule, last run, duration, result, next run, recent history and **Run now**. Tasks that are off say why and link to their setting; destructive ones (Trash purge, Auto-apply) ask first, and Auto-apply's Run now is refused while it is off and never applies more than a scheduled cycle would. Run now is audit-logged (`task_run_manual`); a failed run puts a notice in the bell. Ctrl+K lists the page. New `GET /api/ops/tasks`, `GET /api/ops/tasks/{id}/runs`, `POST /api/ops/tasks/{id}/run`.
- **Update check** as a scheduled task (every 6 hours while *Check for updates* is on): the bell hears of a new version even when nobody opens the app. It shares the Updates page's cache.
- **Subtitle viewer cache clean-up**, daily: expired texts are removed and the cache kept under its size (before, only reading and writing tidied it).
- **Open a worker's page from the main app, signed in.** A worker's page can be reached from the network (its new setting *Reachable from the network*, applied at the next start, or `setup-worker.sh --remote-page`), and the Workers dialog then shows **Open page** for admins. The link goes through the main app, which hands the worker a 60-second, single-use sign-in token for that admin (signed with a key derived from the worker's key; audit-logged as *Worker page opened*); the worker's own password login keeps working. Keep the page on your own network (docs/workers.md, *Worker pages from the network*).
- **Update now for out-of-date workers.** System → Updates shows, per worker, the newest compatible release in the workers' feed and an **Update now** button (admins, audit-logged): the worker finishes its current file, takes no new work, and its host updater installs the release at once, skipping the update hours and the self-update setting but never the compatibility, checksum or idle checks. The page follows the request live (requested, waiting for the current file, updating, done or failed with the reason). It needs the updater on that machine (`setup-worker.sh --self-update-timer`, which now also enables `pmm-worker-update.path`); older workers are updated by hand.
- **Workers can update themselves from your NAS.** The new **Worker update feed** setting (Settings → Workers, advanced; default: the public feed) names the `releases.json` the workers' update timers read, e.g. the NAS's `https://pmm-builds.codershub.me/releases.json`; workers get it with their next check-in. `packaging/flatpak/write-lan-feed.py` writes that feed from the NAS's builds folder, checking each bundle against its `SHA256SUMS`.

### Changed
- The Apple TV profile is now one per model; the old `apple_tv` id still works and means the Apple TV 4K (3rd gen); `samsung_tizen` means the 2020-2021 Samsung sets. The Roku profile now describes the 4K / Ultra models, and the direct-play texts say "devices" instead of "clients".
- The two background loops (services and indexer) are replaced by one scheduler with the same timings: a 5-second tick, Plex every 30 seconds, On Deck every 15 minutes, artwork every 6 hours, the trash purge hourly, the sweep every `index_sweep_hours`, the daily summary and backups at their times; what ran at start-up still does. Each run is recorded in a new table, `task_runs` (the newest 50 per task), created at start-up; tasks not run at start-up pick up from their last run after a restart.
- A failing trash purge, artwork listing or start-up fill is now recorded and reported in the bell (once until it works again) instead of being retried silently.
- Long tasks run on their own threads, so a slow Plex call or backup no longer holds up the other background work.
- `setup-worker.sh --remote-page` / `--no-remote-page` write or remove a systemd drop-in that opens the worker's page to the network (the unit itself is unchanged) and restart a running worker; it prints the firewall step for firewalld, ufw or SteamOS.
- Worker protocol: optional `page` ({host, port, remote}) and `update_status` in the check-in, and `update_feed` and `update_now` in the heartbeat reply (`update_now` in progress replies too). Older workers and main apps ignore them; an older worker gets no Open page link and no Update now button.
- The unused NAS-folder self-update engine (`pmm/safety/self_update.py`) is removed: workers update only through the update timer and the release feed.
