# Plex Media Manager 0.9.0.0

### New
- **Six colour palettes, Harbor by default.** Settings, Account, Appearance now offers Harbor (blue, the new default), Midnight Cobalt, Steel Sky, Tidewater, Nightfall and Copper Reel, each with a light and a dark look that you choose separately from Light, Dark or System; the sign-in, setup and offline pages use Harbor too. The previous gold look is still there as *Classic Gold*, and custom themes you made keep working.
- **An Operator role between viewer and admin.** Operators can run dry runs, Apply, Re-analyse and Restore, answer a film's review questions, start *Look for changes now*, hand back or skip a worker's file, pause or resume workers, and run scheduled tasks (System, Tasks, the one System page they get) including the Plex labels sync, but can't change settings, title rules, users, worker keys, backups or the System pages. Give it to local accounts, or to everyone in a new *Operator group* for OpenID Connect sign-in (Settings, Sign-in); the server checks every call against one table of who may do what, whatever the page shows.
- **A Users list for admins.** Settings, Account, Users lists every account with its role and how it signs in; admins add local accounts, change roles, turn accounts off (signed out at once) or on, and remove them. You can't lock yourself out: your own account and the last admin stay as they are.
- **Personal API tokens for scripts and automations.** Settings, Account, Personal API tokens makes a token with a name, a role (yours or a lower one) and an optional expiry; scripts send it as `Authorization: Bearer pmm_...` to call PMM's API. The token is shown once and only its hash is kept; it acts with no more than your role at the time of each call, stops when your account is turned off or removed, works only for the API (never pages or sign-in), and can be revoked at any time. Wrong tokens are rate-limited on their own, so a broken script never locks anyone out of signing in. Admins see and revoke everyone's tokens. See the API docs for a curl example.
- **The audit log records the role.** Each entry on System, Audit shows whether a viewer, an operator or an admin did it.
- **Open a worker's page from anywhere it shows.** Admins get *Open page* on the Overview's live worker cards and under Settings → Workers as well as in the Workers dialog, so a worker's own page opens signed in, in a new tab, from wherever you see the worker.
- **Turn a worker's page on for the network only while you need it.** Admins can now open a worker's page to the network from the main app for 15 minutes, an hour, four hours or until turned off, and close it again, without touching the worker: it switches within seconds, without a restart and without stopping the file it is working on, shows "Remote page: on until 14:30" and turns itself off when the time is up, even if it can't reach the main app. The worker's own page shows the same with a *Turn off* button. A page fixed by the worker's start command (`--ui-host`) or `PMM_WORKER_UI_HOST` says so instead, older workers show which version they need, and every switch is recorded in the audit log. The worker's firewall still has to let port 8766 through once: `setup-worker.sh --allow-remote-page-toggle` prints that step without opening the page.

### Fixed
- **Workers on other machines no longer pause while Plex streams or transcodes.** A worker's own "Pause while Plex transcodes" rule (an older setting that some workers still send) paused it even when it runs on a different computer than Plex, where pausing helps nobody. Now only a worker on the Plex server's own machine pauses for Plex: one you mark *Runs on the Plex server* (Settings, Workers), or, until you choose, one whose address matches the Plex server's. Your choice always wins, and workers elsewhere keep working.
- **System updaters such as Bazzite's uupd no longer fail on the PMM worker.** A worker built with `setup-worker.sh` kept a stale local build as its Flatpak source, so a nightly `flatpak update` stopped with "Update is older than current version" and took the whole user-apps step with it. Setup and the self-updater now tell Flatpak to skip PMM (it updates itself); it also disables the stale local build remotes (never Flathub); existing workers fix themselves at their next self-update. `setup-worker.sh --unmask-updates` undoes it.
- **Files you skipped on purpose no longer show under Problem files.** Skipping a worker's file is your choice, not a failure, so it is left off the Problem files list and out of the problem count on System health and the file's warning. If a skipped file later fails for real, it shows up again.
- **A main app restart no longer throws away a worker's long read.** When PMM restarted (for example after saving a setting that needs it) while a worker was reading a file's subtitles and speech, the worker was told the task was unknown and dropped minutes of reading, and the file was read again from the start; now the restarted app takes the task back and the worker carries on, so only the quick first look at the file is repeated. Workers need this version too.

### Changed
- **A worker paused by hand says "paused from the main app".** It used to say "paused by an admin", which was no longer true once operators can pause workers too.
- **Operators and viewers see only the Account tab of Settings.** It used to show an error; now it shows their password, language and theme, and says the other tabs are for admins.
- **Workers read a file once for subtitles and the sync check.** When a worker extracts a file's subtitles and listens for speech for the subtitle sync check, one pass over the file now does both instead of reading the whole file twice, which roughly halves that step over a slow share or Wi-Fi; the results are the same, and if the one-pass read fails the worker reads the file the old way.
