# Plex Media Manager 0.6.0.1

### Fixed
- **Two workers no longer work on the same file.** Only the file's current worker may report progress or a result: a worker whose file was queued again, or that the main app forgot after a restart, is told to abandon it (stops its tools, deletes its scratch output, swaps nothing in), and a late result is ignored and logged. A file is queued again only after its worker has been silent about it for 10 minutes.
- **Busy workers no longer show as offline.** Progress reports, results and hand-backs count as contact, and the current file is set as soon as a worker takes it, so the Workers dialog, the Overview cards, System → Health and Updates show it online with its file and percent. A worker renamed on its own page no longer leaves an offline entry under its old name.
- **Worker progress no longer sticks at 0 %.** Every long analysis read (subtitle extraction, the sync-check speech, the full health check, audio decoding, voice detection, transcription) reports how far it is, on the main app and on the worker's own page.
- **Reads that hang now fail instead of blocking a worker.** Every analysis read has a time limit scaled by the file's size, and `mkvmerge -J` and `ffprobe` have their own; the file fails with the step that hung and shows on System → Problem files. The speech read no longer deadlocks when FFmpeg prints many errors.
- **The queue forecast now includes the analysis queue.** A new *Analysis queue finishes* line (Overview and Insights) shows the files waiting for analysis, the measured rate and "about N days, done around <date>", respecting the workers' quiet and pause hours. `GET /api/forecast` gains an `analysis` block.
- **The Overview tells indexed and analysed files apart.** "Files analysed" is now "Files in the index" with a separate "Analysed" tile, and the Video codecs and Resolutions charts show never-analysed files as a "Not analysed yet" bar instead of an UNKNOWN codec or a "?" resolution.
- **Insights no longer counts never-analysed files as fine.** Subtitle coverage has a grey "Not analysed yet" count and its shares, like the codec, language and HEVC-share figures, are of the analysed files. The panels have the normal 16 px spacing and the chart text keeps its normal size at any width (new token `--chart-text-size`).
- **The What's new dialog is short again.** It shows the first sentence of each note (at most 6 per list, "All release notes" for the rest), scrolls inside itself and fits on a phone; `*emphasis*` and `_emphasis_` in release notes are rendered.
- **System → Health no longer warns about the work queue while workers are busy.** It warns only when nothing is running, no worker is busy or has analysed lately, and This server is off. The Overview Activity says files and changes instead of "jobs queued".

### New
- **Hand back / Skip file** for a worker's current file (admins, audit-logged), in the Workers dialog and on the Overview's live cards. Hand back queues the file again for another worker; Skip file fails it ("skipped by <user>") and lists it on Problem files until retried. `POST /api/workers/{name}/task/hand-back` and `/task/skip`.
- **Jobs per worker** (analysis, edits, conversions), set on the main app (Settings → Workers) and on the worker (`--jobs`, `--encoder none`); the stricter wins and existing workers keep every job. Meant for analysis-only CPU VMs with the media mounted read-only (docs/workers.md).

### Changed
- **Update the main app first; then update the workers too.** The main-app update alone already protects 0.6.0.0 workers from working on the same file twice (they are identified by their name header and already follow `cancel`). The workers need 0.6.0.1 for read progress, time limits and jobs per worker. No database change.
- Worker protocol: optional `worker` (and `path`) in progress, done and release reports, `reason` with a `cancel` reply, `jobs` and `writes_media` in the check-in. Main apps and workers of either version keep working together (docs/workers.md, *Protocol additions*).
